``sphinx-matlab-apidoc`` templates
==================================

``sphinx-matlab-apidoc`` renders three `Jinja <https://jinja.palletsprojects.com/>`_
templates, which :confval:`matlab_apidoc_templatedir` can
replace (:doc:`../user-guide/apidoc`). The
defaults are in ``sphinxcontrib/matlab_apidoc/templates/``. They are
rendered with Sphinx's ``ReSTRenderer``, which adds the filters ``e``
(escape reST) and ``heading`` (underline a title; ``heading(2)`` for the
second level).

The variables below are a public interface: new ones may be added in any
release, but renaming or removing one is a breaking change. Every generated
file starts with the marker line ``.. Generated by sphinx-matlab-apidoc.``,
which the command adds outside the templates.

``folder.rst.jinja``
--------------------

One page per folder.

``docname``
   The page, relative to the output folder, without suffix
   (``+demo/index``).
``ref``
   The folder's path reference (``+demo/``; ``./`` for the root).
``title``
   The folder's signature: ``namespace demo``, ``folder utils/``, or
   ``folder ./``.
``kind``
   ``"namespace"``, ``"folder"`` or ``"root"``.
``is_root``
   True for the root folder's page.
``sections``
   ``(title, entries)`` pairs in the order Classes, Functions, Scripts,
   Apps; only sections with entries. ``entries`` are described below.
``subfolders``
   The docnames of the subfolders' pages, relative to this page:
   namespaces, then folders, then ``private/``.
``separate``
   True with :confval:`matlab_apidoc_separate`.
``maxdepth``
   The ``:maxdepth:`` of the toctrees: 4 from the command, any value from
   a script (:ref:`apidoc-write-your-own`). A template can also write
   its own number.
``sidecars``
   The :doc:`sidecar docs <../user-guide/sidecars>` the folder's page
   lists (its own, and those in its ``@`` folders), sorted by file name;
   each a dictionary with ``ref`` (the path reference), ``name`` (the file
   name) and ``docname`` (its own page, relative to this page).
   Empty when sidecar docs are off.
``readme``
   The path reference of the folder's README (any letter case, any page
   suffix), the introduction of its page, or ``None``.

Entries
~~~~~~~

Each entry describes one file:

``ref``
   The file's path reference.
``kind``
   ``"class"``, ``"function"``, ``"script"`` or ``"application"``.
``directive``
   The auto directive, such as ``"mat:autoclass"``.
``options``
   A dictionary of directive options; ``{"members": "", "undoc-members":
   "", "show-inheritance": ""}`` for classes, else empty.
``title``
   The heading: the MATLAB name, or the path reference if MATLAB cannot
   call the file.
``display``
   The name signatures show (the same as ``title``).
``matlab_name``
   The MATLAB name, or ``None`` if MATLAB cannot call the file.
``callable``
   ``matlab_name is not None``.
``private``
   True for files below ``private/``.
``docname``
   With :confval:`matlab_apidoc_separate`: the file's page, relative to
   the folder page. Otherwise ``None``.

``object.rst.jinja``
--------------------

With :confval:`matlab_apidoc_separate`, one page per file. It gets the
variables of one entry, with ``docname`` relative to the output folder.

``sidecar.rst.jinja``
---------------------

One page per sidecar doc (``guide.md`` -> ``guide-md.rst``), with or
without :confval:`matlab_apidoc_separate`. Its title is the sidecar doc's
first heading.
Variables: ``ref``, ``name`` and ``docname`` (relative to the output
folder), as in ``sidecars`` above.
